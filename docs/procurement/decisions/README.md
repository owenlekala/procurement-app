Add a numbered ADR for changes to app boundaries, tenancy, native UI strategy, sealing threat model, financial authority or external integrations. State context, decision, alternatives, consequences and affected requirements/tests. Do not silently replace an accepted decision or use an ADR as permission to claim implementation evidence. Routine compatible implementation choices can proceed within the accepted policy and task scope without a new approval ceremony.
